大模型代码生成过程治理与监控

Spook AI Guard

通过本地 Skill 或插件，将 Codex、Claude Code 等 AI 编码任务的生命周期事件自动上报至治理平台；代码生成前，按仓库、语言和任务场景装配工程规则、历史缺陷库与业务知识库，形成可追溯的生成前上下文。 生成过程中，将计划、工具调用、代码变更、验证结果与风险信号统一记录为质量事件，建立可检索、可回放、可审计的全过程可观测链路；同时通过 GitLab、Codeup 等代码库 API 回读提交、分支、MR 与流水线事件，与本地 Agent 轨迹进行交叉验证与风险识别。 系统依据规则命中、确定性检查、风险等级和验证证据执行质量门禁决策，对低风险变更放行、异常结果进入复核、高风险变更阻断并要求修复重验；最终依据业务规则完成风险路由与责任人推送，将风险项、证据和处置建议定向送达研发、QA 与产运，形成生成前约束、过程观测、门禁决策、结果验证和风险处置闭环。

Agent业务侧落地

QA Manager 与 Feishu CLI

围绕需求进入迭代后的完整质量链路，系统可感知新增 PRD 链接与流程状态，自动触发需求 AC，并在完成后将结果回填原始 PRD。 各关键节点以历史数据和人工结果对模型产出进行对照评估，并通过 OpenRouter 做多模型交叉校验与异常兜底。 生成的测试用例可进一步转换为自动化框架可识别的代码工程，调度真机完成执行与验证，采集核心运行数据并推送结果。

    任务入口

    需求、PRD、MR、测试套件、构建版本与环境约束。

    输入保持业务语义
  2. 02

    不复制领域实现
  3. 03

  4. 04
    执行层

    交付与回读

QA Manager

质量工程编排层

统一工作站准备、设备与构建发现、账号前置、视觉服务、真实设备执行、数据归档、报告和只读数据核验。 它提供一致入口，但不接管各领域模块的实现。

入口
统一命令、结构化输出和明确退出状态，减少不同工具的调用差异。
环境
可重复初始化工作站并校验依赖版本；不覆盖无法识别的既有目录，外部信任阻断可从已完成阶段恢复。
资源
按顺序准备构建、账号、视觉服务和设备；设备租约与心跳仍由设备提供方负责。
恢复
区分前置条件阻断与自动化失败，保留已完成阶段、失败阶段和幂等恢复入口。
健康
对设备、构建、账号、视觉服务、运行器和报告交付做功能性检查，而非只检查进程存在。
边界
不实现设备传输、账号业务、OCR/CV 算法、飞书字段映射或产品页面断言。

Feishu CLI

项目工作流接口

把需求、PRD、评审、验收标准、测试用例、MR 白盒分析、缺陷、文档和项目字段作为一套可读写的业务模型， 让 Agent 不依赖平台页面操作完成交付。

读取
从完整工作项地址解析项目，读取需求、PRD、关联关系、MR 和目标字段。
生成
生成 Review、AC、测试用例和白盒报告；PRD 不可读时失败关闭，不导入不完整结果。
持久化
写入文档、测试管理、测试计划、工作项字段与关系；缺陷按具体问题独立创建。
预演
通过 dry-run 或 no-upload 分离读取、生成与正式写入，降低首次执行风险。
补偿
根据接收记录和持久化字段判断是否需要重放，只补偿结果缺失或已经失效的任务。
验收
重新读取目标字段、关系、文档内容和权限；仅返回成功码或本地产物不算完成。

执行协议

一次任务的状态流转

  1. 01解析需求与边界
  2. 02检查服务与权限
  3. 03准备构建与夹具
  4. 04执行独占资源
  5. 05验证断言与运行数据
  6. 06回写文档与字段
  7. 07回读持久化确认
  8. 08释放租约与现场

任务终态区分 completed、failed 和 blocked。失败保留数据；阻断保留所缺前置条件；恢复只从已确认的阶段继续。

能力所有者必须保持的不变量
跨域编排QA Manager只组合能力；输出可解析；失败状态与恢复动作明确。
项目语义与写回Feishu CLI先读后写；写后回读；生成、导入、字段写回和通知分别报告。
设备传输与租约设备控制层独占租约、心跳和超时释放；不绕过忙碌设备。
账号与业务前置账号服务按场景准备夹具；凭证不进入任务参数、报告或数据。
识别与业务断言视觉服务 / 业务运行器算法与页面语义保留在领域模块；编排层只管理生命周期。
交付数据运行器 + Feishu CLI截图、录屏、结果、文档权限和字段链接共同通过后才算完成。

大模型效果评估

多模型横向对比与业务适配验证

探索选型阶段，围绕活动、App 与小游戏等真实需求，对 Haiku、Sonnet、Opus、GPT-5.4、GPT-5.5、DeepSeek 开展横向测试，并通过 Union 多模型并行生成改善用例质量与产出数量。 产品回归阶段，以版本化评测集和 Baseline / Candidate A/B 为统一契约，将确定性规则、产品 Judge 与独立 Shadow Judge 分层组合，持续记录候选胜率、Judge 覆盖率、P95 延迟、成本、任务状态与证据引用，综合判断不同模型在具体业务任务中的效果、稳定性与成本差异。

JD Match · Business Evidence

从评测资产到平台化的业务证据链

将模型评测岗位高频要求绑定到真实业务任务、产品适配器和运行证据，呈现的不只是关键词，而是能力、机制与结果之间的对应关系。

  1. 01 · ASSET Benchmark / Regression

    7 个真实需求覆盖活动、App 与小游戏；版本、SHA-256 和 Baseline / Candidate 让同一任务可以重复回归。

  2. 02 · JUDGE Rules + LLM Judge

    Yovela 用泄漏、空输出、语言漂移、截断和 Turn 失败守底线；Cuddmi Multi-Judge 与 Shadow Judge 独立复核。

  3. 03 · METRIC Agent Task Metrics

    Mochi 对话、Cuddmi 记忆、Yovela 叙事统一记录 Winner、Judge Coverage、P95、Cost 与任务状态。

  4. 04 · RCA Failure RCA

    Failed、Blocked、Timeout 与 Stale 分开归因；逐 Case 保存错误摘要和 Evidence Ref，避免环境失败污染质量结论。

  5. 05 · GATE Quality Gate

    候选胜率、Judge 覆盖、P95、成本、阻断上限与零容忍规则共同形成 PASS / FAIL / BLOCKED / N/A。

  6. 06 · PLATFORM Platformization

    3 个固定业务适配器由 Worker 领取任务，以租约、心跳、幂等键和不可变归档支撑复用；Yovela 接入 3/3 检查通过。
