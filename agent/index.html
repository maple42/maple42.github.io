职责划分

Agent 与 Harness 分别负责什么

Agent 负责判断、规划和生成；Harness 负责上下文、权限、执行环境、异常恢复与验证。 这套分工让任务能够暂停、复核和恢复，而不是只得到一次模型输出。

质量工程控制平面

qa-manager 与 feishu-cli

这不是把多个脚本包进同一个命令，而是把任务语义、资源所有权、执行状态、失败恢复和交付验证分层。 qa-manager 只负责跨域编排；具体能力仍由各自模块拥有，避免形成难以维护的巨型工具。

  1. 01
    任务入口

    需求、PRD、MR、测试套件、构建版本与环境约束。

    输入保持业务语义
  2. 02
    qa-manager / 编排层

    配置发现、环境准备、命令选择、资源顺序、状态汇总和恢复入口。

    不复制领域实现
  3. 03
    领域适配层

    feishu-cli、设备、构建、账号夹具、OCR/CV、业务运行器与只读分析。

    所有权保持独立
  4. 04
    执行层

    独占资源、真实应用、稳定业务锚点、断言、截图、录屏和运行轨迹。

    失败同样保留现场
  5. 05
    交付与回读

    用例、报告、缺陷、附件、状态与字段写回，并重新读取持久化结果。

    写入成功不等于交付完成

qa-manager

质量工程编排层

统一工作站准备、设备与构建发现、账号前置、视觉服务、真实设备执行、证据归档、报告和只读数据核验。 它提供一致入口，但不接管各领域模块的实现。

入口
统一命令、结构化输出和明确退出状态，减少不同工具的调用差异。
环境
可重复初始化工作站并校验依赖版本；不覆盖无法识别的既有目录，外部信任阻断可从已完成阶段恢复。
资源
按顺序准备构建、账号、视觉服务和设备；设备租约与心跳仍由设备提供方负责。
恢复
区分前置条件阻断与自动化失败，保留已完成阶段、失败阶段和幂等恢复入口。
健康
对设备、构建、账号、视觉服务、运行器和报告交付做功能性检查，而非只检查进程存在。
边界
不实现设备传输、账号业务、OCR/CV 算法、飞书字段映射或产品页面断言。

feishu-cli

项目工作流接口

把需求、PRD、评审、验收标准、测试用例、MR 白盒分析、缺陷、文档和项目字段作为一套可读写的业务模型， 让 Agent 不依赖平台页面操作完成交付。

读取
从完整工作项地址解析项目，读取需求、PRD、关联关系、MR 和目标字段。
生成
生成 Review、AC、测试用例和白盒报告；PRD 不可读时失败关闭，不导入不完整结果。
持久化
写入文档、测试管理、测试计划、工作项字段与关系；缺陷按具体问题独立创建。
预演
通过 dry-run 或 no-upload 分离读取、生成与正式写入，降低首次执行风险。
补偿
根据接收记录和持久化字段判断是否需要重放，只补偿结果缺失或已经失效的任务。
验收
重新读取目标字段、关系、文档内容和权限；仅返回成功码或本地产物不算完成。

执行协议

一次任务的状态流转

  1. 01解析需求与边界
  2. 02检查服务与权限
  3. 03准备构建与夹具
  4. 04执行独占资源
  5. 05验证断言与证据
  6. 06回写文档与字段
  7. 07回读持久化确认
  8. 08释放租约与现场

任务终态区分 completed、failed 和 blocked。失败保留证据；阻断保留所缺前置条件；恢复只从已确认的阶段继续。

能力所有者必须保持的不变量
跨域编排qa-manager只组合能力；输出可解析；失败状态与恢复动作明确。
项目语义与写回feishu-cli先读后写；写后回读；生成、导入、字段写回和通知分别报告。
设备传输与租约设备控制层独占租约、心跳和超时释放；不绕过忙碌设备。
账号与业务前置账号服务按场景准备夹具；凭证不进入任务参数、报告或证据。
识别与业务断言视觉服务 / 业务运行器算法与页面语义保留在领域模块；编排层只管理生命周期。
交付证据运行器 + feishu-cli截图、录屏、结果、文档权限和字段链接共同通过后才算完成。

状态管理 · 异常恢复

Harness 运行时

Harness 运行时

Harness 承接模型之外的执行责任：维护任务状态、工具权限、环境隔离、异常路径与恢复策略， 让一次执行能够安全暂停、重试和继续。

  • 状态
    状态可见

    区分进行中、完成、阻断和残余风险，避免假完成。

  • 工具
    调用受控

    统一工具输入输出、错误语义和权限范围，减少隐性副作用。

  • 恢复
    执行可恢复

    失败时关闭高风险动作，并从有记录的节点继续工作。

持续运行状态管理失败关闭异常恢复

评测与门禁

评测、复核与结论范围

将工程规则、确定性检查、多模型复核与人工判断组合使用。 已有场景完成真实验证；对尚不足以形成稳定结论的方向，明确标记为扩大验证中。

  • 检查
    确定性门禁

    用测试、静态检查、权限与结果回读守住质量底线。

  • 复核
    独立复核

    候选结论经过证据校验，只有通过校验的增量可以进入产物。

  • 边界
    结论边界

    区分已验证、局部验证与扩大验证中，不用演示结果替代生产证据。
