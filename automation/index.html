自动化职责

让系统承担重复执行，
让人专注于风险与判断。

每一次自动执行都要有明确入口、可追踪状态和可复核结果。 成功时沉淀证据，失败时保留现场并进入恢复路径，而不是静默结束。

实现架构

原生动作稳定执行，
OCR / CV 穿透 UI 树盲区，大模型视觉兜底。

业务用例只描述要完成的动作和判断。结构化 UI 优先处理稳定控件，OCR 识别多语言文字， CV 覆盖图标、Canvas 与游戏画面；当传统识别结果缺失或置信度不足时，由大模型视觉理解进行语义兜底， 最终统一交给 Airtest 执行原生设备动作，并把现场证据带回协作链路。

01

语义与识别解耦

用例保持 find、click、exists、input、assert 等业务语义，不把脚本锁死在单一识别技术上。

02

多模态能力互补

Poco / UIAutomator 读取结构化控件，OCR 处理多语言文字，CV 覆盖图标、Canvas 与游戏画面，大模型视觉负责低置信结果的语义兜底。

03

原生动作与证据闭环

Airtest 统一触摸、滑动、输入、应用生命周期和截图，异常同样保留现场并回写结果。

TRIGGER · EXECUTE · VERIFY · WRITE BACK

端到端编排

从协作节点出发，
把结果带回现场。

项目节点或协作动作触发任务后，系统获取必要上下文，完成代码与变更分析，生成测试资产， 调度真实设备执行，再把结论、附件和状态回写到原协作节点。

  • 触发
    飞书与项目流程接入

    将评审、验收和测试节点转成结构化任务，保留来源与处理状态。

  • 分析
    代码上下文与风险识别

    提取与改动相关的信息，为测试设计和执行范围提供依据。

  • 生成
    测试资产自动准备

    在规则约束下生成测试用例与执行输入，并保留人工复核入口。

  • 执行
    真实设备任务编排

    统一设备租约、安装、账号前置、动作运行、录屏和现场采集。

  • 回写
    证据与状态闭环

    将通过、失败、待确认与阻断如实回写，避免只返回一句完成。

RECOVER · RESUME · PRESERVE EVIDENCE

异常恢复

失败不消失，
任务可以继续。

网络波动、设备占用、账号前置不满足或外部系统暂时不可用，都应成为明确状态。 自动化保留现场、释放资源，并从可恢复节点继续，而不是重复整条链路。

  • 隔离
    资源边界清晰

    设备、账号与任务保持独占关系，异常不会扩散到其他运行实例。

  • 恢复
    从最近可信节点继续

    保留完成状态与中间产物，避免恢复时重复执行已确认步骤。

  • 兜底
    人工判断有明确入口

    遇到权限、业务决策或环境阻断时，主动转交并说明所需动作。

状态机失败留证资源释放断点恢复人工接管
